# 歌曲列表虚拟化

## Goal

旧审计记录过本地音乐库「歌曲」列表全量渲染 592 行（19,353 DOM 节点 / 598 张封面全解码），但当前 HEAD 已存在 `MediaList` 虚拟化和 worker 可见区间请求链路。目标先在生产等价构建上复测真实运行态；仅当全量渲染仍能重现时，修复最小的可见区间或视口几何问题。最终让歌曲列表稳定保持窗口行渲染、封面按视口解码，并保证视觉与交互无回退。

## Requirements

1. **实测先行**：使用带 `custom-protocol` 的生产等价 Tauri 构建，记录构建来源、`data-virtualized`、viewport `clientHeight` / `scrollHeight`、渲染行数、图片数、DOM nodes、renderer WS/PB。
2. **条件修复**：若 DOM nodes 已 ≤2,500 且渲染行数符合可视区 ± 缓冲行，不做推测性源码修改，只记录旧基线已过期；若仍全量渲染，修复最小的 range/geometry contract。
3. **虚拟化落地**：列表仅渲染可视区 ± 缓冲行，保留当前 worker-owned visible-range 数据流。
4. **行为保真**：滚动平滑（现有滚动位置保持）、单选/多选、上下文菜单、拖拽（若有）、键盘导航（↑↓/Home/End）、播放头和首图懒加载正常。
5. **边界**：全量数据仍由 worker/数据层持有；排序、过滤、刷新和播放上下文保持。
6. **回归**：滚动 5 屏无行为异常、无空白闪烁；选中状态跨滚动保持；上下文菜单位置正确。
7. 与 07-16-scroll-dom-observers（P1 list DOM hot paths）不重叠：本任务只处理歌曲列表虚拟化契约；observer 热路径仍归原任务。

## Acceptance Criteria

- [x] 生产等价运行态证据完整，歌曲列表虚拟化生效（DOM nodes ≤2,500 @50% 滚动位置；封面按视口解码）。
- [x] 交互回归清单全绿（滚动/选中/菜单；播放头因测量 sidecar 无活动歌曲而 N/A；组件无行级键盘/拖拽契约）。
- [x] 若基线仍全量渲染：同场景修复前后 renderer WS 或 PB 至少下降 25 MB；若当前基线已达标：明确记录旧审计与当前构建来源差异，不虚构前后收益。首次同进程样本为 WS -29.9 MiB / PB -26.2 MiB；配对 GC 复测为 -21.3/-21.4 MiB，波动已记录。
- [x] typecheck 与任务相关测试全绿；无视觉回归（CDP 截图对比列表首屏）。全量 `npm test` 为 520/521，唯一失败属于相邻 Streaming v2 常量漂移，不在本任务修改范围。
