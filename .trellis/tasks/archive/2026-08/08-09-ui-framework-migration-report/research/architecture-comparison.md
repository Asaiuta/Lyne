| 维度 | A. 保持 Tauri + 优化 | B. Avalonia(.NET) | C. Rust 原生 UI（egui/iced） | D. 混合（主窗 WebView + 部件原生化） |

| 内存收益（vs 现状 idle 495 MB） | −17 ～ −160 MB（trim 已落地 0；可选项 disable-gpu −108 PB；v2 −48~−112） | −300 ～ −400 MB（预计整树 150–200 MB） | −330 ～ −420 MB（预计整树 90–170 MB） | −60 ～ −200 MB |

| 运行时/发布 | 不变（WebView2 已随系统） | 新增 .NET（自包含 +60–100 MB 安装） | 无新运行时 | 不变 |

| 生态 | 现有全部测试/自动化（CDP 驱动、WMI 采样、bench）可沿用 | CDP 自动化失效（需新 UI 自动化），bench 不变 | 同上 | 主窗沿用 CDP |

> **补录 Slint（2026-08-09）**：初版矩阵将 Rust 原生统称 egui/iced，遗漏了 Slint（声明式 .slint + Skia 自绘，Rust 原生零运行时）。它是 **C 大类中视觉上限最高的选项**：内置渐变/阴影/透明度/动画关键帧与官方设计器，比 egui/iced 高约一档（C 行保真度可按 50–70% 理解），工程量 55–95 人日档。但**不改变全局结论**：同为全量重写（106.4K 行 Solid 前端 + parity 动效资产；AMLL 级歌词 canvas 仍不可行），内存收益同档（−330~−420 MB）；主决策（保持 Tauri、混合渐进）不变。

> **补录 Qt（2026-08-09）**：Qt 此前未出现在任何评估中。定位：C++/QML 原生渲染（Qt Quick + RHI，无 WebView 固定成本），内存预期 ~120–260 MB 整树，视觉保真与 Avalonia 同档（60–75%：QML easing/动画/透明度覆盖较好，毛玻璃与 Web 级排版仍受限，AMLL 级歌词 canvas 不可行）。工程量 51–91 人日（见 §3 表）。**独有额外代价**：C++/QML 技能栈、Qt 运行时依赖（+30–80 MB 分发）、**许可证合规（LGPL 或商业授权）**。判级与 Avalonia 相同（全量重写/视觉风险/双轨维护），**不改变主决策**；若未来启动全量原生，排序建议 B(>Qt) > Slint > egui-iced。

## 4. 行为事实（实测校正常见误判）

1. WebView 的 463–605 MB 是 **Chromium 固有基线**（渲染/GPU/网络进程），当前前端已虚拟列表、无 DOM/JS 泄漏——不存在"代码浪费"可省。
2. 播放 222 MB sidecar 与 UI 架构**无关**（解码内核与 IPC 复用），Avalonia 方案省不掉它。
3. 前端非 React 而是 SolidJS（106K 行、512 文件）——任何迁移都是全量重写，不能复用 90% 的组件代码。
4. 现有自动化堆（CDP UI 驱动、WMI 采样、401 Rust test、520 vitest）是 Tauri 特有资产——切 Avalonia 时需要全新 UI 自动化壳。

## 5. 决策建议

**结论：保持 Tauri（方案 A）为主路径；D（混合）作为渐进优化；B/C 切换只在触发条件达成时才重新评估。**（补充：若未来启动全量原生，首选 Slint；Qt/Avalonia 同判级，因 C++/.NET 栈与许可证/运行时成本不作首选。所有补充方案均不改变主结论。）

触发器（任一满足时，重启评估并更新本报告）：
1. 产品出现 <300 MB 空闲内存的硬性发布指标（如低配设备/驻留常驻场景），且 trim 已执行仍不达标；
2. 视觉风格转向"完全原生桌面"（放弃 Web 风格 parity，SPlayer parity 路线终止）；
3. 团队明确反偏好 WebView 技术栈（维护/安全面）。

当前（2026-08-09）：**不切换**。收益为 300–400 MB 内存换 50–80 人日 + 视觉保真损失 + 技术栈替换，且已有无损替代路径（trim: −17～−160 MB 已就绪部分）。建议先执行 trim 落地清单，积累"优化后仍超标"的证据再决策。
