# Design — 旧归档任务验收证据重建

## 范围与对象

处理对象：`archive/2026-06/` 与 `archive/2026-07/` 下带"归档一致性注记"的 19 个任务 PRD + `archive/2026-08/07-18-fix-orphaned-local-library-media` 的 1 条剩余未勾选。共计约 120 条验收条目。

## 证据分级（S1/S2/S3）

| 级别 | 来源 | 可判定性 |
| --- | --- | --- |
| S1 | 任务目录内记录：implement.md 验证记录、validation-evidence.md、check.jsonl 指向的结果文件、research/ 下结论 | 强：作者自证，直接对应 |
| S2 | git 提交：提交信息含任务关键词（slug 词根）、提交 diff 与验收点描述的代码/测试变更对应 | 中：实现存在 + 变更内容匹配 |
| S3 | 仓库内测试与产物：测试套件名与验收点对应且代码库现存、bench/report JSON、spec 文档引用验收行为 | 中弱：现状可验证，但无法证明归档时点通过 |

## 判定规则

对每条验收条目：

1. 提取验收点核心名词/行为（如"无目录时摘要为空"、"--enforce 非零退出"）。
2. 依次查询 S1 → S2 → S3。
3. 判定：
   - **达成**：S1 直接记录通过，或 S2 实现提交 + 对应测试现存且仓库状态未变（验收点为行为/覆盖类）；勾选 + 附来源。
   - **部分**：有实现或部分测试但验收点整体无法证实（如"端到端前端行为"只有后端测试）→ 不勾选，记录部分证据。
   - **不可重建**：无 S1，S2 找不到对应提交，或提交内容与验收点不匹配 → 不勾选，判定为不可重建。
4. 所有"达成"必须能回溯：commit hash 可 `git show`，文件路径存在。

## 工作流

1. 盘点：逐任务读取 prd 验收点 + 任务目录文件清单 + check.jsonl 条目。
2. 考古：`git log --all --oneline --grep=<任务关键词>` 找候选提交；`git show --stat <hash>` 核对；按需 `git log -S<字符串>` 找行为引入点。
3. 核实：候选测试/产物路径在 HEAD 存在性检查（`git ls-files` / 文件系统）。
4. 判定 + 写矩阵 + 更新 PRD（勾选/注记替换）。
5. 复核：脚本核对矩阵 ↔ PRD 勾选一致性；全仓 validate。

## 输出

- `research/evidence-matrix.md`：任务 × 条目 × 判定 × 证据级别 × 来源引用。
- 各 PRD：勾选状态 + 来源注记（替换上一轮的模板注记，未勾选条目保留具体判定结论）。
- 预估产出形态：S1/S2 证据充分的条目（2026-07 部分任务有 implement.md 验证记录）勾选；2026-06 PRD-only 任务大部分判定"不可重建"。
