# 重建旧归档任务验收证据

## Goal

为 2026-06/07 时代归档且验收框未勾选的任务（19 个任务 + 07-18-fix-orphaned-local-library-media 剩余 1 条）重建逐条验收证据：从仓库可验证来源（git 提交、测试、产物、研究文件）判定每条验收标准是否达成；有证据的勾选并注明来源，无证据的保留未勾选并给出判定结论，替换上一轮任务写入的模板式"归档一致性注记"。

## Requirements

- 覆盖全部 19 个标注"归档一致性注记"的归档任务，以及 07-18 未勾选的前端空状态条目。
- 逐条验收标准的判定必须来自仓库内可验证来源：任务目录内记录（implement.md 验证记录、validation-evidence.md、check.jsonl 指向的结果文件）、git 提交（提交信息/文件变更与验收点对应）、仓库内测试与产物（测试套件名、bench/report JSON、spec 文档引用）。
- 判定规则固定：直接证据充分 → 勾选并附证据来源；部分证据 → 不勾选但记录部分证据；无证据 → 不勾选并判定"证据不可重建"。
- 产出证据矩阵（research/evidence-matrix.md），覆盖每个任务、每条未勾选/勾选条目、证据分级与来源引用。
- 不得为通过率而伪造验收；勾选与否必须与证据矩阵一致。

## Acceptance Criteria

- [x] `research/evidence-matrix.md` 覆盖全部 20 个任务与所有验收条目，每条含：判定（达成/部分/不可重建）、证据分级（S1 任务内记录 / S2 git 提交 / S3 测试与产物）、具体来源引用（commit hash、测试套件、文件路径）。
- [x] 判定为"达成"的条目在对应 PRD 中勾选，并附证据来源注记；判定为"部分"或"不可重建"的条目保持未勾选，PRD 注记替换为具体判定结论（不再是模板文本）。
- [x] 每个任务的判定过程可复核：矩阵中每条证据可回溯到仓库内真实对象（hash 可 `git show`，路径存在，测试套件可运行或曾有运行记录）。
- [x] 无任何条目在缺乏直接证据的情况下被勾选；矩阵与 PRD 勾选状态双向一致。
- [x] 全仓 `task.py validate`（活动 + 归档）零失败；证据重建工作按既有流程提交并归档。

## Notes

- 本轮任务只处理元数据与文档，不修改任何产品代码；不重跑旧测试，除非某条目需要补验（列为"可补验"而非直接勾选）。
- 2026-06/07 时代任务多为 PRD-only 归档，预期相当比例条目判定为"不可重建"——该判定本身是有效产出。
